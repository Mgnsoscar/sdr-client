Editing while holding: the elapsed window

While a run is parked at its Hold, the edit dialog shows the whole sequence for context — but everything left of the Hold has already happened. It should read as elapsed at a glance and refuse edits outright: no drag handles, no double-click editor, no delete; a click just tells you when it ran. The Hold itself is now and can’t move either. Only the post-hold window (the resumed remainder of a crossing ramp, the down-ramp, the cool-down) stays live. Three treatments below — switch between them; the first is the recommendation.

Elapsed window treatment
Details

A · Frosted & lockedrecommended

The elapsed window keeps its full geometry (you still see what led to the hold) under a frosted wash; its steps go monochrome, lose their handles, and each carries a ✓ ran mark with the real clock time. A ribbon at the top says why it’s locked. Nothing else changes, so the post-hold window looks exactly like the normal editor.

B · Ghosted outlines

Lighter touch: no wash, the elapsed steps become dashed outlines with faint labels and the ✓ marks. Cleaner, but a ghosted ramp can still look “pending” rather than “done”, and the boundary between locked and editable relies on the Hold edge alone.

C · Collapsed strip

The elapsed window folds into a narrow summary (“4 steps ran · 1:45”) with an expand chevron, giving the editable window the whole canvas. Best when window A is long, but you lose the at-a-glance context of what the signal was doing when it paused.

Elapsed = read-only, everywhere

Hit-testing ignores elapsed steps for drag, resize, anchor handles, double-click and Delete; the context menu shows only Ran at 12:04:31. The row header greys them and adds a lock. A crossing ramp’s run-up is elapsed; its remainder (right of the Hold) is not.

The Hold is now

The enter edge carries a live ⏸ HOLDING 04:12 tag instead of the offset chip, and the marker can’t be dragged or removed (the dialog already refuses a Hold-less edit). The on-air pill dims: T0 is history, resume is the reference the editable window hangs off.

Post-hold = the normal editor

Right of the resume edge everything works as today: the resumed remainder is its own ramp (pre-filled), the down-ramp and cool-down drag, anchor and edit; validation and the Ready pill apply only to this window.

Real behaviour behind the picture: the elapsed set is every step whose fires all sit at or before the Hold instant (the agent’s window A), which the client already knows from the run’s hold_at_offset_s; the canvas needs a “locked before x” mode and the hit-test/paint gates — no wire or agent change.
