# Packaging sdr-client as a standalone, no-admin, self-installed Windows app

**Status: DONE (client-only).** The client freezes to a self-contained Windows
folder with PyInstaller and wraps into a per-user (no-admin) installer with Inno
Setup. This document is the build + install + distribute guide.

Two hard constraints drove every choice below:

1. **No administrator rights** — the installer and the app install and run
   entirely per-user (no elevation, no `Program Files`, no machine-wide
   registry, no service).
2. **Unknown-publisher execution is often blocked** — there is **no code-signing
   certificate**, so Windows SmartScreen *will* flag a freshly-downloaded copy.
   §5 is the honest answer for that; it is a distribution problem, not something
   the build can paper over.

Target: **Windows 10/11 x64.** Build host: **a Windows PC** (a Windows `.exe`
can't be reliably cross-built from Linux). Provisioning (`Provision unit…`) is
**in scope**, so an agent bundle is shipped.

---

## 0. TL;DR — build it

On a Windows 10/11 x64 machine, from a fresh checkout of this repo:

```powershell
# one-time: install Python 3.11 or 3.12 (per-user, python.org) and
#           Inno Setup 6.3+ (per-user, https://jrsoftware.org/isdl.php)

# (optional, for Provision unit…) drop the agent bundle in first:
#   copy sdr-agent-<ver>.tar.gz  ->  bundles\

powershell -ExecutionPolicy Bypass -File packaging\build.ps1 -Clean
```

Produces:

- `packaging\Output\SDR-Broadcaster-Control-1.0.0-Setup.exe` — the per-user installer.
- `dist\SDR-Broadcaster-Control-1.0.0-portable.zip` — a no-installer fallback
  (unzip anywhere, run the `.exe`).

`build.ps1` creates an isolated `.venv-build`, installs `requirements.txt` +
PyInstaller, runs `sdr_client.spec`, zips the folder, and (if it finds
`ISCC.exe`) compiles the installer. Nothing it does needs admin.

## 1. What the app is

- **`sdr-client`** — the PyQt6 fleet-control + calibration GUI. It talks to
  on-unit agents over HTTP + mDNS; it does **not** need `sdr-agent` /
  `sdr-scripts` present to run.
- **Entry point:** `main.py`, app name **"SDR Broadcaster Control"** (the
  product name, the shortcut name, and the per-user data-folder name).
- **Runtime deps:** `requirements.txt` (the real client set — NOT the larger
  agent-test list in `CLAUDE.md`): PyQt6 (+ optional PyQt6-QScintilla), httpx,
  pydantic v2, zeroconf, websocket-client, PyYAML, paramiko.
- **Icon:** `ui/assets/app.{ico,png}` — a placeholder "SDR" wordmark generated by
  `packaging/make_icon.py`. Replace those two files with real artwork to rebrand;
  the spec and installer pick them up automatically.

## 2. What got built (the pieces)

| File | Role |
|------|------|
| `paths.py` | **The load-bearing change.** Single source of truth for the per-user writable data dir + read-only resource dir (see §6). |
| `sdr_client.spec` | PyInstaller `--onedir` freeze. Committed (the `*.spec` gitignore was overridden). |
| `packaging/installer.iss` | Inno Setup per-user (`PrivilegesRequired=lowest`) installer. |
| `packaging/build.ps1` | The Windows one-shot build pipeline. |
| `packaging/make_icon.py` | Regenerates the placeholder icon (build-time only; needs Pillow). |
| `bundles/` | Where you stage `sdr-agent-*.tar.gz` for `Provision unit…` (tarballs gitignored). |

## 3. Prerequisites on the Windows build PC (all per-user, no admin)

- **Python 3.11 or 3.12**, x64, from python.org — "Install for me only" (avoid
  the newest release until PyQt6 ships wheels for it; `requirements.txt` floats
  versions so pip grabs matching wheels).
- **Inno Setup 6.3+**, from <https://jrsoftware.org/isdl.php> — installs per-user;
  gives you `ISCC.exe`. (Only needed for the installer; skip it and you still get
  the portable ZIP.)
- Git (or just download the repo zip).

## 4. Building

`packaging\build.ps1` does everything (see §0). Useful switches:

- `-Clean` — wipe `build\ dist\ .venv-build\` first (from-scratch build).
- `-SkipInstaller` — stop after the frozen folder + ZIP (no Inno Setup needed).
- `-Python <path>` — pick a specific interpreter (default: `py -3`, then `python`).

The freeze is **`--onedir`, not `--onefile`** on purpose: a plain folder launches
fast and trips AV / SmartScreen **less** than a self-extracting onefile `.exe`.
UPX is off for the same reason.

**The version** shown in the installer / filenames is `#define AppVersion` at the
top of `packaging/installer.iss` — bump it there for a new release (and keep the
`AppId` GUID unchanged so upgrades/uninstall stay coherent).

## 5. Installing (per-user, no admin) + the unknown-publisher reality

**The installer** (`...-Setup.exe`):
- installs to `%LOCALAPPDATA%\Programs\SDR Broadcaster Control`,
- adds a per-user Start-menu shortcut (desktop shortcut optional, off by default),
- registers a per-user uninstall entry,
- never asks for admin. On uninstall it removes the program folder + shortcuts
  but **leaves the user's data** in `%APPDATA%\SDR Broadcaster Control` (so a
  reinstall keeps units/plans/caches).

### Unknown publisher / SmartScreen — the honest part

There is **no signing certificate**, so there is **no way to make Windows treat
this as a known publisher.** Be upfront with coworkers/IT rather than pretending
around it. What actually helps, roughly best-first:

1. **Distribute through the company's software portal / Intune, or ask IT to
   allow-list the app** (by hash or install path). In a locked-down shop this is
   the sanctioned route and it **sidesteps SmartScreen entirely.** Prefer it.
2. **Ship the portable ZIP (onedir folder) + a shortcut**, not the downloaded
   `Setup.exe`. An unsigned *folder of files* launched by a shortcut trips
   SmartScreen far less than a downloaded unsigned *installer .exe*. (Not a
   guarantee — but materially better when option 1 isn't available.)
3. **"More info → Run anyway"** on the SmartScreen dialog — the manual override,
   *if* company policy leaves it enabled (confirm; many locked-down environments
   disable it, which is exactly why options 1–2 come first).

**Do not** propose a self-signed certificate — trusting one requires admin on
every coworker's machine, so it doesn't help here.

If a real cert is obtained later, that's the proper fix — see §7.

## 6. Where the app keeps its state (the writable-state relocation)

A frozen, per-user-installed app runs from a read-only location, so the client
can no longer write its config next to its own source. `paths.py` moves all
writable state to a **per-user data directory**:

- **Frozen:** `%APPDATA%\SDR Broadcaster Control\` (Windows). A starter
  `units.yaml` is seeded there on first launch.
- **From source (dev + the test suite):** the repo root — byte-for-byte the old
  behaviour, so nothing about development or the ~680-test suite changed.
- **Override:** set `SDR_CLIENT_DATA_DIR=<path>` to force a location (handy for a
  portable "data next to the app" setup, or for testing).

Relocated files: `units.yaml`, `plans.json`, `schedule.json`, `library.json`,
`components.json`, `address_cache.json`, `calibration_cache.json`,
`unit_ledger.json`. Read-only bundled assets (the IBM Plex fonts, the icon, the
agent bundle) stay inside the app and are resolved via `paths.resource_dir()` /
each module's own resource lookup.

## 7. Provisioning bundle (`Provision unit…`)

The feature SSH-bootstraps a fresh Pi and pushes it an agent OTA bundle. To
include it, drop `sdr-agent-<version>.tar.gz` (built by
`sdr-agent/deploy/build_bundle.sh`) into `bundles\` **before** building; the spec
collects it and `state/agent_bundle.py` finds it inside the frozen app. Without
it the app still runs — the feature just has nothing to deploy. The tarball is
binary and versioned out-of-band, so it is gitignored, not committed.

## 8. If you get a code-signing certificate later

This is the single biggest lever on SmartScreen. Then:
- **OV** Authenticode: signs the `.exe`/installer, but SmartScreen reputation
  still has to *build up* over downloads before warnings go quiet.
- **EV** Authenticode (hardware token): **instant** SmartScreen reputation;
  pricier; the token must be present at sign time.
- Sign both the app `.exe` (add a `signtool` step after PyInstaller) and the
  `Setup.exe` (Inno Setup `SignTool` directive). Wire it into `build.ps1`.

## 9. What was validated, and what you must smoke-test on Windows

**Validated on Linux (in CI/dev)** via a `--onedir` smoke build: the spec
collects everything (Qt plugins, fonts, icon, `units.yaml`, the native wheels),
the frozen app boots headless, seeds `units.yaml` into the data dir, loads the
bundled fonts, and starts zeroconf mDNS discovery + the poller with **no import
errors**. The three usual PyInstaller gotchas here — `zeroconf`, `paramiko` /
`cryptography`, `pydantic` v2 — are handled in the spec (whole-package submodule
collection; `cryptography` collected whole so the floating version's
paramiko-optional submodules are always present).

**Must be smoke-tested on a clean Windows 10/11 x64 VM** (no Python, no Qt
installed) — the Linux build can't cover these:
- the `.exe` launches and the window + taskbar show the icon;
- the installer installs per-user with **no admin prompt**, shortcuts work,
  uninstall is clean;
- discovery finds a real unit on the LAN, and `Provision unit…` deploys the
  bundled agent (if in scope);
- data lands in `%APPDATA%\SDR Broadcaster Control`, not next to the app.

## 10. Guardrails

All of this is **client-only and additive**. Nothing here touches the
drift-guarded files (`api/argspec.py`, `api/ramp.py`, `state/power_law.py`) or the
`sdr-agent` / `sdr-scripts` repos. No capability or version bump — packaging
changes no wire behaviour.
